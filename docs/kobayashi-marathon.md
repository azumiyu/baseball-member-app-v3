# 小林の走れ！マラソン！

`/game/kobayashi-marathon` で遊ぶ、チーム全員で同じ小林に給水するゲームです。YGミニゲーム一覧から開けます。画像は `public/homepage/introduce/4.JPEG` をもとに作成した、透明な4コマの `public/game/kobayashi-runner.png` を使用します。

## ルール

- 小林は1分に300m（秒速5m）で走り続けます。累計kmは全員共通で、ページを閉じてもリセットされません。
- 最後に誰かが給水してからの秒数に応じて、通常は1秒あたり1mLの水をあげられます。給水すると全員共通の渇きがリセットされ、直後はほとんど飲めません。
- 給水ボタン1回で、その時点で飲める量をあげます。飲める量はサーバーが計算し、画面の量は目安として表示します。
- 給水直後の10秒間は休憩します。全員を合わせて受理できる給水は最大6回/分です。
- 「ちょうのどかわいた！！」は給水量2倍、「ランナーズハイ中！！」は半分です。
- 各メンバーがあげた水の累計で競います。DBにはmLの整数、画面にはLで表示します。通常のゲームの自己ベストとは別の累計ランキングです。

初回の走行開始時点では5分ぶんの渇きがあるため、最初の訪問者も給水できます。状態の抽選は3分の時間枠ごとで、6分の1で渇き2倍、6分の1でランナーズハイとなり、その枠の最初の1分間だけ有効です。同じ開始時刻と経過時間から全員に同じ状態を返し、再読み込みでは抽選し直しません。

## DB負荷と保存

距離・渇き・状態変化は保存したタイムスタンプから計算します。毎秒のDB更新、常駐処理、定期ジョブはありません。走行アニメーションとカウンターはブラウザー内で更新します。

- 画面への入場や手動更新：認証・共有状態・ランキング・自分の直近の給水結果を1回のSELECTで取得します。
- 給水成功：確認用SELECT、3つの書き込みをまとめたD1のbatch、最新状態のSELECTです。
- 連打・休憩中・すでに他の人が給水した画面：状態を読み直すだけで、給水の書き込みは行いません。同時操作でCASに負けたbatchも水量を加算しません。
- 自動ポーリングはしません。画面を離れてから戻り、最後の取得から60秒以上経っているときだけ更新します。ほかの人の給水は、自分の給水操作や更新時に反映されます。

保存行数は、共有状態の `marathon_state` が1行、`mini_game_scores` と `mini_game_runs` がそれぞれ参加メンバーにつき最大1行です。全給水履歴は蓄積しません。

共有状態のrevisionを比較して更新し、給水量・個人の累計・再送確認用の結果を同じトランザクションで保存します。サーバーが毎回生成するwrite tokenで関連する加算を制限するため、同時給水や通信の再送で二重加算しません。通信失敗時は同じrequest IDとrevisionで再試行します。クライアントから送った量や時刻はスコア計算に使用しません。

## 初回のDB移行

アプリの更新を公開する前に、既存のD1へ `drizzle/0018_kobayashi_marathon.sql` を一度だけ適用します。既存の選手・認証・ミニゲーム用テーブルがある環境を対象とします。適用済みの移行や初期化用seedを再実行しないでください。

この移行は共有状態の1行を作り、その適用時刻から走行を開始します。既存ゲームの記録には変更を加えません。週次Workerの更新は不要です。

ローカルDBに適用する場合のコマンドです。

```powershell
npx wrangler d1 execute yg_member_db --local --persist-to="./.wrangler/state" --file="./drizzle/0018_kobayashi_marathon.sql" --config="./dist/server/wrangler.json"
```

本番では、アプリの `DB` バインディングが指すD1へ同じ移行SQLを適用してからアプリを更新してください。この実装作業では既存DB・本番DBへ移行を実行していません。

## 実装と検証

| 場所 | 役割 |
| --- | --- |
| `lib/games/marathon.ts` | 距離・給水量・共有状態変化の計算とAPI型 |
| `lib/games/marathon-store.ts` | 認証・共有状態・累計・再送確認の取得と保存 |
| `app/api/games/marathon/route.ts` | 専用のGET / 給水POST |
| `components/games/MarathonPage.tsx` / `Marathon.module.css` | 給水所、走行演出、操作、ランキング |
| `components/games/useMarathonApi.ts` | 通信、再試行、共有状態の取得、サーバー時刻補正 |
| `scripts/verify-marathon.cjs` | 隔離したD1でのルール・保存の回帰検証 |
| `scripts/verify-marathon-ui.cjs` | 時計・通信回数・再送・画面表示の回帰検証 |

```powershell
node scripts/verify-marathon.cjs
node scripts/verify-marathon-ui.cjs
```

既存のローカルDBや本番DBを使わず、距離と渇き、倍率、累計加算、同時給水、同じ操作の再送、権限・認証、保存行数を確認します。画面側では仮想の時計と通信で、経過中の無通信、再試行、競合、非表示時の停止と復帰、倍率・累計表示を確認します。ブラウザーでの見た目と実機の操作確認は別途必要です。
