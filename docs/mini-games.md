# YGミニゲーム

YGチームメニューの「YGミニゲーム」から遊びます。ログイン中のメンバーを使用し、ゲーム別に各メンバーの自己ベストと上位10名を表示します。スコアが同じ場合は達成日時が早い順、さらに同じ場合はメンバーID順です。

## 川高の振れ！チンチロ！

親は川高固定で、画像は `public/game/kawataka.PNG` を使います。持ち金はゲーム内の仮想の円で、100万円から開始し、5ターン終了時の残高を競います。掛け金はターンごとに1円以上・現在の持ち金以下の整数で指定します。途中で0円になると終了します。実際の入金・換金はありません。

1. 親が先に振り、役が出るまで最大3回振ります。
2. 親がヒフミ・目なし・ションベンなら、その場でプレイヤーの勝ちです。
3. それ以外はプレイヤーが最大3回振り、役が出た時点で親と比較します。
4. 勝敗に応じて持ち金を更新し、次のターンへ進みます。

| 役 | 条件 | 強さ・精算 |
| --- | --- | --- |
| ピンゾロ | 1・1・1 | 最強。勝ち側の倍率は5倍 |
| アラシ | 2・2・2～6・6・6 | ピンゾロに次ぐ。同じ役では数字が大きい方が強く、勝ち側の倍率は3倍 |
| シゴロ | 4・5・6 | アラシに次ぐ。勝ち側の倍率は2倍 |
| 通常の目 | 同じ数字2個と異なる数字1個 | 異なる数字が目。6～1の順に強く、勝ち側の倍率は1倍 |
| 目なし | 3回以内に役が出ない | 1倍負け |
| ヒフミ | 1・2・3 | 2倍負け |
| ションベン | サイコロが丼からこぼれる | 1倍負け。1回の投擲ごとに0.1% |

同じ強さの役は引き分けで残高は変わりません。勝敗の精算では、掛け額に倍率を掛けた金額を加減します。役同士の倍率は重ね掛けせず、残高の下限は0円です。例えば親がヒフミならプレイヤーは掛け額の2倍を得て、親が目なし・ションベンなら1倍を得ます。

## 押野の出せ！剛速球！

`/game/oshino-fastball` で遊ぶ一球勝負のタイミングゲームです。画像は `public/game/oshino.PNG` を使用し、振りかぶった押野のリリースに合わせて投球します。目標となるリリース時刻は開始から2,400～3,600msの間で抽選します。

入力時刻は `performance.now()` を使った経過時間で計測し、描画フレーム数では判定しません。サーバーに保存した目標時刻との差から球速を計算します。

- 球速は0.00～200.00 km/h、小数点以下2桁で表示します。
- 目標との差が±0.005ms以内だけ200.00 km/hです。それ以外は最大199.99 km/hで、1msの差なら199.23 km/hになります。
- 目標から離れるほど球速が下がり、下限は0.00 km/hです。1球で終了し、その球速が自己ベストを上回った場合に保存します。
- 保存するスコアは球速を100倍した整数です。例えば199.23 km/hは `19923`、最大値は `20000` です。表示はカタログの `scoreScale: 100` と `precision: 2` で変換します。

小数点以下2桁の記録のため同点は発生します。同点時は他のミニゲームと同じく、達成日時が早い順、さらに同じ場合はメンバーID順です。

## 保存とランキング

- `mini_game_runs`：ゲームID・メンバーIDにつき現在のプレイを1行だけ保持します。ターン、残高・スコア、終了状態、リクエストID、ゲーム固有の準備状態または直近の演出結果を保存します。チンチロは再読み込み後も現在のターンから続けられます。
- `mini_game_scores`：ゲームID・メンバーIDにつき自己ベストを1行だけ保持します。終了したプレイのスコアが自己ベストを上回った場合に更新します。チンチロは最終持ち金、剛速球は100倍した球速を保存します。
- 全ターンのログや過去のプレイ履歴は蓄積しません。プレイ回数が増えても保存行数は増えず、ゲーム数×メンバー数に比例します。
- ランキング用の複合インデックスで、対象ゲームの上位10名を取得します。画面表示のために全プレイの履歴を集計しません。
- サイコロの抽選、役判定、残高計算、投球の目標時刻の抽選、球速の計算、ランキング更新はサーバーで行います。クライアントから申告されたスコアを採用しません。
- ログインCookieからメンバーを特定します。開始・ターン進行の再送時は同じリクエストIDを使い、同じ操作を二重に精算しないようにします。

APIは `/api/games` です。GETの `game` パラメーターでゲームIDを指定し、認証・現在のプレイ・ランキングを1回のSELECTで取得します。POSTは `gameId`・`requestId`・`runId`・現在の `turn` と、ゲームに応じた `action` を送ります。

| action | ゲーム | 追加項目・処理 |
| --- | --- | --- |
| `start` | 共通 | 初回は `runId: null`・`turn: 0`。ゲームごとの初期状態を作成 |
| `turn` | チンチロ | `bet` で掛け金を指定し、親とプレイヤーの1ターンを精算 |
| `pitch` | 剛速球 | `elapsedMs` に0～10,000の有限数を指定し、1球を判定 |

剛速球の開始時は `result_json` に `{ kind: "fastball-ready", releaseMs }` を保存し、投球後はその結果に置き換えます。クライアントの指定した目標時刻ではなく、保存済みの `releaseMs` を計算に使います。

開始時は現在のプレイ1行を作成・更新し、ターンの精算時は同じ1行を更新します。終了時に自己ベストを更新する場合だけ、記録の更新を同じD1のbatchに追加します。自己ベスト以下なら記録用SQLも省略します。投擲アニメーションや振り直しごとの通信・定期取得は行いません。プレイIDとターン番号の照合で、別タブの古い画面からの二重進行も防ぎます。

## ゲームの追加・調整

| 場所 | 役割 |
| --- | --- |
| `lib/games/catalog.ts` | メニューのゲーム名・説明・画像・画面URL、スコアの表示倍率と桁数 |
| `lib/games/chinchiro.ts` | チンチロの役判定、勝敗、倍率、振り直し・終了回数、こぼれる確率 |
| `lib/games/fastball.ts` | 剛速球の目標時刻、タイミング差と球速の計算、最高球速の範囲 |
| `lib/games/registry.ts` | ゲームID・種別に対応するサーバーのルール処理 |
| `lib/games/api-types.ts` | 画面とAPIで共有するリクエスト・レスポンス型、ゲーム別の結果を受け取るジェネリック型 |
| `lib/games/store.ts` / `app/api/games/route.ts` | 認証、状態・自己ベスト保存、API入口 |
| `components/games/` | ゲーム画面、通信フック、共通ランキング表示 |
| `components/games/FastballPage.tsx` / `app/game/oshino-fastball/page.tsx` | 剛速球の計測・投球演出・結果画面 / ページ入口 |

新しいゲームはカタログ、サーバーのルール処理、対応する画面を追加します。チンチロと異なるプレイ状態・演出が必要な場合は共有型と保存APIのアダプターも拡張し、判定をUIに移さないでください。同じ2テーブルをゲームIDで分けて利用できるため、ゲームの追加だけで履歴テーブルを増やす必要はありません。

ルール変更で過去スコアと比較できなくなる場合はゲームIDを新しくし、別ランキングとして扱ってください。カタログの `version` だけを増やしても、既存DBのランキングは分かれません。

## DBへの適用と公開

`0009_schedule_lineups.sql` まで適用済みのDBに、`0010_mini_games.sql` を一度だけ追加適用してください。このSQLは上記2テーブルとランキング用インデックスを作成します。既存のチーム・予定・道具・成績は変更しません。

「押野の出せ！剛速球！」は既存の2テーブルを別のゲームIDで利用します。`0010` が適用済みなら追加のDB移行は不要で、アプリの更新だけで反映できます。

ローカルでは既存のアプリ用設定を使います。

```powershell
npx wrangler d1 execute yg_member_db --local --persist-to="./.wrangler/state" --file="./drizzle/0010_mini_games.sql" --config="./dist/server/wrangler.json"
```

本番ではCloudflareのD1コンソールから、アプリの `DB` バインディングが指す本番DBへ `0010_mini_games.sql` を実行します。Wranglerを使う場合は同じ本番DBのIDが設定されたファイルを指定し、`--remote` で実行してください。適用済みのSQLや `seed.local.sql` は再実行しません。

適用後にアプリを公開します。今回のミニゲーム追加で週次LINE・週次スケジュールWorkerの変更はありません。

## 手元での確認項目

- ログイン後にYGチームメニューからゲームを開き、メンバー名とランキングを確認できること。
- 100万円・1ターン目から始まり、5ターンまたは残高0円で終了すること。
- 親の抽選を先に表示し、最大3回の振り直し、役と倍率、引き分けが正しく表示されること。
- 親がヒフミ・目なし・ションベンのとき、プレイヤーの抽選を行わず決着すること。
- 通信失敗後に再試行しても二重にターンや残高が進まず、再読み込みで現在の状態を復元できること。
- 終了時に自己ベストだけが更新され、低いスコアで過去の自己ベストを上書きしないこと。
- 別メンバーでログインしてプレイし、ゲーム別のランキングへメンバー名で反映されること。
- スマホで掛け額・開始・サイコロ操作・結果の確認ができること。
- 剛速球の1球で0.00～200.00 km/hの結果が表示され、小数点以下2桁を保って自己ベストとランキングに反映されること。
- 剛速球の画面から再挑戦でき、チンチロの持ち金・ランキングと混ざらないこと。
- 剛速球で通信を再試行しても同じ投球を二重保存せず、低い球速で自己ベストを上書きしないこと。
