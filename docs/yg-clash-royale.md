# YGクラロワ

`/game/yg-clash-royale` で遊べる、写真のメンバーを召喚するリアルタイム防衛ゲームです。自分のタワーを守りながら、倒した敵の撃破ポイントを競います。相手のキングタワーはなく、敵は上側の増援ゲートから押し寄せます。自陣HPが0になると終了します。

## 遊び方

- 出撃前に8枚のデッキを編成します。同じカードを重複して入れることはできません。
- 手札を選び、味方陣地に出撃させます。エリクサーを消費し、使ったカードは控えのカードと入れ替わります。
- 地上・空中、単体・範囲攻撃、遠距離・近距離などの相性で迎撃します。味方は攻撃できる敵を探し、敵がいない間はレーン上側で待機します。
- 時間がたつほど敵の編成と物量が厳しくなります。残り時間による強制終了はなく、城を守れる限り続きます。
- 敵を倒すとキャラごとのポイントを獲得します。強敵ほど高得点で、部隊は1体ごとに加算します。タワーの迎撃や味方の退場時爆発で倒した敵も対象です。通常の攻撃ダメージや味方の退場では加点しません。
- 自分のタワーが倒れた瞬間までの撃破ポイントが記録され、自己最高のみランキングに残ります。同じtickの撃破も計上し、同じ敵の撃破は二重に数えません。

カードの写真は既存の七色のシンカー・ミニゲーム素材を参照します。追加の外部画像サービスや生成画像への通信はありません。

| カードの例 | 得意な対処 |
| --- | --- |
| メガ千明 | 着地衝撃と範囲攻撃で地上の群れを迎撃 |
| ラーメン根岸プリンス | 移動後の突撃で単体に大ダメージ |
| カワタカ部隊 | 4人で単体攻撃の強敵を取り囲む |
| ゴトウシンカー | 遠距離・小範囲の減速で時間を作る |
| 三澤ローボールドラゴン | 飛行して地上専用の敵を範囲攻撃 |
| 小林マラソンライダー | 速さを生かし、抜けた地上の敵を迎撃 |
| 阿部シールドガード | 一度きりのシールドで大きな攻撃を受ける |

ほかにも北澤・池原・八巻・川鍋・菅・石畑・押野・長安・堀江・芝田の計17キャラ。既存写真に鎧・杖・槍・盾・翼などの描画を重ねています。カードを選んで戦場をタップするほか、左右の配置ボタンでも出撃できます。キーボードは1〜4で手札選択、戦場上で矢印・Enter、Pで一時停止。動きを減らす設定にも対応します。

キャラクター図鑑では、それぞれの得意な相手・苦手な相手と全17人の相性表を確認できます。同じ強さのカードを各1枚出した戦闘を、タワー支援なしで両方向から検証した目安です。配置、コスト、相手の強化、周囲の援護によって戦況は変わります。相性は事前計算済みで、画面上で戦闘を再計算したりDBに問い合わせたりしません。

スマホの戦闘中は画面全体を使い、スコア、戦場全景、タワーHP、エリクサー、手札、配置ボタンを表示します。縦画面では操作欄を下に、横画面では右に置き、戦場を切り抜かず縮小します。戦場の余白は出撃位置に含めません。「図鑑・相性」ボタンで休憩して図鑑を開き、「バトルに戻る」で再開できます。

参考にした基本要素は、[Supercellの公式ゲーム紹介](https://supercell.com/en/games/clashroyale/)と[エリクサーの説明](https://support.clashroyale.com/hc/en-us/articles/49484936933403-Elixir)にあるリアルタイムのカード出撃・時間で回復するコストです。本ゲームのキャラ、数値、防衛戦、増援、戦闘計算、画面は独自実装です。

## 通信とD1

描画と操作はブラウザー内で行い、サーバーにも同じ固定ステップの決定的エンジンを用意します。サーバーが受け取るのは出撃の入力履歴と進行先tickだけです。クライアントが送るスコア、城HP、ユニット状態は採用しません。

- 1 tickは50ms。1回のチェックポイントは最大200 ticks（10秒）です。
- 通常は10秒分をまとめて送信し、サーバーが保存済み状態から再計算して確定します。毎フレーム・毎攻撃のDBアクセスはありません。
- GETは既存の認証・再開データ・ランキングをまとめたSELECTを1回実行します。
- 保存状態のJSONはSQLite側で再シリアル化せずテキストのまま読み、JavaScriptで解析します。エリクサーや座標の小数精度が保存・読込で変わり、正常な対戦が不一致扱いになることを防ぎます。
- 途中チェックポイントは認証SELECT 1回と、確定状態を保存するUPDATE 1回です。終了時に自己最高を更新する場合だけ、スコアUPSERTを同じD1バッチに加えます。
- 開始時は既存の `mini_game_runs` に1人1ゲーム1行を保存し、自己最高は `mini_game_scores` に1人1ゲーム1行を保存します。履歴を無限に蓄積するテーブルは作りません。
- 追加migrationや専用テーブルは不要です。既存のミニゲーム用テーブルを使います。

## 再開・整合性

チェックポイントは `runId` と `turn` を条件に保存します。別タブや並列リクエストが同じ状態を二重に進めることはできません。同じ `requestId` の直後の再送は確定済みの結果を返し、古い操作は409で競合を知らせます。

ゲーム開始から実際に経過していないtickへの早送りはサーバーで拒否します。ブラウザーを閉じている時間に敵が自動進行することはありません。非表示中はローカルの進行を止め、200msを超えて非表示になった場合は保存し、再表示で自動再開します。手動の休憩は再開ボタンを押すまで維持します。

一時的な通信失敗では休憩に切り替えず、同じrequestIdと入力を1・2・4・最大8秒の間隔で自動再送します。未確定の先行計算は最大20秒に制限し、それを超えると「保存待ち」で進行を待ち、保存できたら自動で続行します。照合はJSONのキー順に依存せず、小数の微差だけを許容します。確定状態を基に未保存の入力を再計算して表示へ戻すため、差分が積み重なることも防ぎます。認証切れや実際の状態競合では保存済み状態の確認が必要です。

プレイ中も保存する瞬間にログインと在籍状態を再確認します。ログアウト済み・セッション失効・退団済みの状態では結果を保存できません。

通常は数KBの状態だけを保持し、ユニットは全体96体・片側48体、演出は24件までに制限します。出現数の上限でも敵の強化は進むため、部隊を無限に蓄積して端末を圧迫する作りにはしません。終了条件は自陣HP0で、固定の制限時間はありません。

一時停止では未保存分をまとめて保存します。ブラウザーや端末を強制終了した場合は、最後に保存できたチェックポイントからの再開となります。

## 検証

`node scripts/verify-yg-royale-api.cjs` は隔離されたMiniflareの実D1に全migrationを適用して、入力検証、サーバー再計算、10秒上限、早送り拒否、再送、並列保存、認証、ランキングを検証します。本番DBや認証情報は使用しません。Windowsではworkerdの子プロセス起動許可が必要な場合があります。

```powershell
node scripts/verify-yg-royale.cjs
node scripts/verify-yg-royale-arena.cjs
node scripts/verify-yg-royale-matchups.cjs
node scripts/verify-yg-royale-session.cjs
node scripts/verify-yg-royale-ui.cjs
node scripts/verify-yg-royale-api.cjs
node node_modules/typescript/bin/tsc --noEmit --incremental false
node scripts/run-framework.mjs build
```

撃破ポイント、旧データの隔離、終了tickの加点、再計算、小数の実D1往復、全289組の相性、戦場の座標変換、通信再送と非表示からの再開、画面操作とスマホ用の高さ配分を検証します。画面・音・タッチ端末の実機確認を代替するテストではありません。
