# 成績と予定の連携

成績入力はスケジュールに登録された試合を選んで行います。日付・開始時刻・大会名・対戦相手で試合を判別し、オーダーと成績は同じ `schedule_games.id` に連携します。同日の複数試合も別のIDなので、試合番号や並び順から相手を推測しません。

予定の日付・時刻・大会名・対戦相手を変更しても、同じ予定IDへの連携は保たれます。成績の保存キーは既存の `game_date` / `game_number` のまま保持し、表示には連携先の予定情報を使います。日付変更のために成績・打席を削除して作り直す処理はありません。

## 既存成績と予定削除

移行時に同じ日付の成績が1件、予定も1件だけある場合は、自動で連携します。成績か予定のどちらかが同日に複数ある場合、予定がない場合は連携しません。第1試合・第2試合という番号だけでは実際の予定を決めません。

未連携の成績は引き続き表示・編集できます。管理者は内容を確認して登録済みの予定へ明示的に連携できます。同じ予定へ複数の成績を連携することはできません。試合を判別できなければ未連携のまま保持します。

予定を削除すると成績の `schedule_id` だけをNULLにし、成績・打席は残します。未連携の履歴は従来の保存日付で確認できます。出欠・試合別スタメンの削除は従来の予定削除の仕様どおりです。

## DBへの適用と公開順序

更新したアプリの公開前に `0011_stats_schedules.sql` を一度だけ適用します。`0010_mini_games.sql` まで未適用の移行がある場合は先に順番に適用してください。`0010` 適用済みのDBでは `0011` だけを実行し、適用済みSQLや初期化用の `seed.local.sql` は再実行しません。

ローカルDB用の適用コマンドです。これは手動適用のための手順で、この変更作業では実行していません。

```powershell
npx wrangler d1 execute yg_member_db --local --persist-to="./.wrangler/state" --file="./drizzle/0011_stats_schedules.sql" --config="./dist/server/wrangler.json"
```

本番ではアプリの `DB` バインディングが指すDBへ未適用分を実行してからアプリを公開します。この機能のための週次Workerの変更はありません。

`0011` が追加する内容は以下です。

- `stats_games.schedule_id`: NULLを許す予定ID。予定削除時は `ON DELETE SET NULL`。
- `stats_games_schedule_id_unique`: 1つの予定に対応する成績を1件に制限するインデックス。NULLの既存成績は複数保持できます。
- 成績と予定が同じ日付に各1件だけある組み合わせの連携。主キーと成績・打席の子テーブルは変更しません。
- 連携済み予定の削除前に成績revisionを増やすトリガー。予定削除と同じトランザクションで更新し、削除前に開いた成績画面から古い連携を保存する競合を検出します。
- 移行完了時の成績revision更新。

トリガー `schedule_games_stats_revision_before_delete` は手書きの移行SQLに含めています。Drizzleのスナップショットはテーブル・インデックスの定義を記録し、トリガーの定義はこのSQLで管理します。

## 取得・保存と通信量

成績のGETは既存の認証・成績取得と同じSELECT内に予定情報をまとめます。画面で試合を選ぶたびに予定APIを呼ぶ処理や、試合数・選手数に比例するSELECTの繰り返しは追加しません。初回の成績取得は従来どおり全履歴で、予定情報を含める分だけ読み取る行とレスポンスサイズは増えます。

試合候補は今後の予定・直近20件の過去予定・成績に連携済みの予定を初回に取得します。「さらに過去の試合を表示」で `/api/stats/schedules` から20件ずつ追加します。この取得では出欠・成績の明細を返しません。

保存は引き続き `partial: true` で変更した試合と削除した試合だけを送ります。サーバーも対象試合の成績・打席を読み、変更のあるテーブルだけを書き換えます。予定IDと既存の保存キーの対応を保つため、予定を切り替えるだけで新規成績を作ったり、別試合を削除したりしません。自動保存の待ち時間とrevisionによる競合検出は維持します。

## 手元での確認項目

- 同日に2件の予定を登録し、それぞれの成績・打席を入力して、切り替え・再読み込み後も別々に残ること。
- 成績とオーダーで同じ試合を選んだときに、日付・開始時刻・大会名・対戦相手が一致すること。
- 連携先の予定の日付・時刻・大会名・相手を変更しても、元の成績・打席をその予定から表示できること。
- 予定を削除しても成績・打席が履歴に残り、削除前に開いていた成績画面からの保存は競合として扱われること。
- 既存の成績と予定が各1件の日付だけ自動連携され、同日複数の成績・予定は未連携のまま残ること。
- 未連携の成績を表示・編集でき、管理者だけが対象予定を選んで連携できること。他の成績が連携済みの予定へ重複連携できないこと。
- 試合切り替えに伴う追加GETや、変更していない試合のPUTが発生しないこと。保存中の追加入力と同時編集の競合を確認すること。

この変更では実DBへの接続・移行SQLの適用・バックアップ・ビルド・デプロイ・ブラウザーによる動作確認は実施していません。
