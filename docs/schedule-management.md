# スケジュール・出欠管理

予定は日付ごとに確認でき、同じ日に複数の試合を登録できます。各予定には日時、大会名、対戦相手、集合場所と「未確定」「打診中」「確定」を保存します。日付だけが必須で、開始時刻は未設定または7:00〜19:00の30分刻みから選べます。既存の時刻がこの範囲外の場合も保持します。出欠は予定ごとに「参加」「不参加」「未定」とコメントを記録し、回答していない選手は未回答として区別します。

予定は初期状態では折りたたみ、日付・開始時刻・大会名・対戦相手・場所・自分の出欠を一覧表示します。予定をタップすると、その試合の詳細と入力欄が開きます。別の予定を開くと前の予定を閉じます。

大会名・対戦相手・場所は検索付きの候補選択です。候補は `name_options` に保存し、場所は `kind = 'location'` として共有します。取得済みの予定の名前も候補に含め、新しい名前の追加や未設定への変更もできます。候補の検索自体は取得済みデータを使い、API・DBアクセスを増やしません。大会名は `title` に保存し、連携中のオーダーの大会名へ反映します。

場所の候補検索中は、入力した場所名をGoogleマップ・Appleマップで検索できます。保存済みの予定からも場所名で地図を開けます。地図URLの入力欄はありません。既存の `map_url` 列は互換性のため保持します。

## 編集できるメンバー

| 操作 | 対象 |
| --- | --- |
| 予定・全員の出欠・コメントを見る | ログイン済みのメンバー |
| 予定を登録・編集・削除する | オーダー編集権限を持つ5名（安曇・戸田・押野・池原・根岸） |
| 自分の出欠・コメントを保存する | ログイン中の本人 |
| 他の選手の出欠・コメントを保存する | 管理者2名（安曇・戸田） |
| チーム名・監督名を変更する | 管理者2名（安曇・戸田）。チーム設定から変更 |

判定は既存の `can_edit_lineup` / `is_admin` と端末に紐付いた選手IDを使用します。予定編集者でも、管理者でなければ他人の回答を変更できません。画面とAPIの両方で制限します。権限の初期設定は [メンバーログインと権限](member-login.md) を参照してください。

スケジュール画面の「あなたの出欠」から、本人が自分の出欠・コメントを入力します。管理者は「全員の出欠・コメント」を開き、対象選手の「編集」から他人の回答も変更できます。出欠・コメントは自動保存されます。

## ログイン時の未回答案内

ログイン後の初回取得時に、今日以降の予定で自分の回答がない場合は「出欠が未入力の試合があります！」とポップアップで案内します。日付は日本時間で判定し、過去の予定は対象にしません。スケジュール以外のタブを表示していても案内します。

「参加」「不参加」に加え、明示的に「未定」を選んだ予定も回答済みです。未定は未回答の案内に含めません。ポップアップからワンタップで「未定」「参加」「不参加」を回答でき、スケジュール画面へ移動することもできます。「あとで」または閉じる操作で、その画面を開いている間の案内を終了します。ログイン後に追加された予定を理由に、この未回答案内が繰り返し表示されることはありません。

## 予定変更の案内

今日以降の回答済み試合で、開始時刻または場所が変更された場合だけ「予定が変更された試合があります！」と案内します。変更した本人には表示しません。大会名・日付・対戦相手・未確定などの状況の変更は案内の対象外です。

直前の開始時刻・場所の変更前後を表示します。複数回変更された場合は最新の変更前後で、個人が最後に確認した時点からの全履歴ではありません。「変更なし」で現在の出欠とコメントを保ったまま確認済みにでき、出欠が変わる場合はその場で「未定」「参加」「不参加」を選べます。「あとで」で閉じた変更は同じ画面内では再案内しませんが、次のログインでは未確認分を案内します。

## オーダーへの反映

オーダー画面では各メンバーの背番号の左に「参加」「不参加」「未定」「未入力」を表示します。スタメン・DH投手・ベンチ・不参加の各欄が対象です。「未入力」は未回答を意味し、オーダーの配置から回答を推測しません。独立した出欠一覧パネルは表示しません。

出欠バッジは閲覧用です。出欠やコメントの確認・編集はスケジュール画面で行います。予定未連携時と対象予定の切り替え直後は、バッジを非表示にして旧予定の回答を表示せず、保存後に選んだ予定の回答を表示します。

毎週日曜0時（日本時間）に、次の土曜日に登録された予定をオーダーへ反映します。同じ土曜日に複数ある場合は開始時刻の早い予定を選びます。時刻未入力の予定は後に並び、同時刻の場合は予定IDで順序を固定します。土曜日の間は当日の予定を対象にします。

対象の土曜日に予定がなければ、現在の日付・試合情報・選手配置を保持します。日曜の処理後に予定を追加した場合も、オーダーの日付が過去になっていれば、その土曜日の予定を反映します。週次Workerが実行されなかった場合は、アプリのチーム情報取得時にも同じ更新を補完します。

オーダーの試合選択は、登録済みの今日以降の試合を日付・時刻付きのプルダウンから選ぶ形です。日付や大会名・相手・時刻・場所をオーダー側で直接入力する欄はありません。「スケジュールで編集」は選択した試合の編集欄を開き、未連携の場合は現在の試合情報を新規予定の初期値にします。スケジュールの変更と空欄はオーダーへ反映し、対象予定を明示的に選んで保存する場合はその選択を優先します。

予定の編集画面から確認操作を経て削除できます。連携中の予定を削除した場合、別の対象予定があればそちらを反映し、対象がなければ連携を解除して現在のオーダー内容を保持します。削除した予定の出欠・試合別スタメンも削除します。成績は予定との連携だけを解除し、成績・打席を履歴に残します。成績入力も同じ予定IDを使い、予定の日付変更後も連携を保ちます。適用が必要な `0011_stats_schedules.sql` と既存成績の扱いは [成績と予定の連携](stats-schedules.md) を参照してください。

各試合のスタメンは、オーダー形式・打順・守備位置・選手・DH投手を保存し、試合を切り替えると復元します。ベンチ・不参加の一覧や登録名簿は試合別に複製しません。保存のない試合は現在のオーダーを引き継ぎ、その試合の出欠を反映します。過去試合のスタメン保存は週次更新や関連する保存処理で削除します。予定・出欠の履歴は残します。

チーム名「YGファイヤーズ」と監督名「池原　海斗」は共通のチーム設定です。オーダーに入力欄はなく、管理者だけがチーム設定から変更できます。APIでも管理者権限を確認します。

出欠の反映は、オーダーの対象予定に回答した現役選手だけに適用します。

- 「不参加」：スタメン・DH投手から外し、不参加に入れます。空いた打順の選手は自動選出しません。
- 「参加」：不参加から外します。すでにスタメンの選手はそのままで、不参加だった選手はベンチに戻ります。
- 「未定」・未回答：現在の配置を保持します。

対象予定で「不参加」の選手は、オーダー側でスタメンへ移して保存しても不参加に戻ります。出場させる場合は本人または管理者がその予定の出欠を変更してください。

## DBへの適用と公開順序

アプリと週次スケジュールWorkerの公開前に、未適用のSQLを `0007_schedules.sql` → `0008_schedule_updates.sql` → `0009_schedule_lineups.sql` の順で一度だけ実行します。`0007` まで適用済みなら `0008` と `0009`、`0008` まで適用済みなら `0009` だけです。

`0007` は予定を保存する `schedule_games`、予定・選手ごとの出欠とコメントを保存する `schedule_responses`、予定用のrevisionを追加します。`team_settings` には連携する予定ID、開始時刻、集合場所、地図URLと週次更新の記録を追加します。予定は空から開始し、既存の名簿・オーダー・道具・成績を保持します。同日複数の予定はそれぞれ異なるIDで管理します。

`0008` は試合の確定状況、変更番号、回答の確認済み番号と履歴取得用インデックスを追加します。`0009` は時刻・場所の直前値と変更者、試合別スタメン用の `schedule_lineups` / `schedule_lineup_slots` を追加し、既存の場所名を `name_options` に登録します。移行前の変更番号は確認済みに揃え、移行後の時刻・場所の変更から案内します。

ローカルDBに適用する場合は、既存のアプリ用設定を使用します。

```powershell
npx wrangler d1 execute yg_member_db --local --persist-to="./.wrangler/state" --file="./drizzle/0007_schedules.sql" --config="./dist/server/wrangler.json"
npx wrangler d1 execute yg_member_db --local --persist-to="./.wrangler/state" --file="./drizzle/0008_schedule_updates.sql" --config="./dist/server/wrangler.json"
npx wrangler d1 execute yg_member_db --local --persist-to="./.wrangler/state" --file="./drizzle/0009_schedule_lineups.sql" --config="./dist/server/wrangler.json"
```

本番ではCloudflareのD1コンソールから、アプリの `DB` バインディングが指す本番DBへ未適用分を実行します。Wranglerを使う場合も、その本番DBのIDが設定されたファイルを指定してください。既存データの移行では、適用済みSQLや初期化用の `seed.local.sql` を再実行しません。

移行後にアプリを公開し、新しいWorkerを公開します。

```powershell
npx wrangler deploy --config="./workers/weekly-schedule/wrangler.jsonc"
```

Worker名は `yg-weekly-schedule`、実行設定は `0 15 * * SAT`（土曜15時UTC＝日曜0時JST）です。`workers/weekly-schedule/wrangler.jsonc` のD1バインディングをアプリと同じDBにしてください。このWorkerにLINE用のSecretは不要です。既存の `workers/weekly-equipment` は独立した金曜のLINE通知Workerです。

## 保存と同時更新

予定・出欠は正規化テーブルへ差分保存します。予定保存と関連するオーダーの変更は、予定・チームの両revisionを照合し、同じD1のbatchで反映します。同時編集でrevisionが変わっている場合は409を返し、古い画面から上書きしません。週次Workerとアプリ内の自動更新も同じ処理を使います。

予定APIの初回取得は今日以降だけで、過去の予定は「過去の予定」を開くと20件ずつ読み込みます。日付・IDのカーソルを使い、履歴が増えても初回に全件読み込みません。編集で必要な単一予定の取得にも対応します。PUTは `partial: true` と変更した `data.games`、削除した `removedGames` を送り、取得していない過去の予定は削除しません。

認証と必要なデータの取得は1回のSELECTにまとめます。チーム取得・連携保存では対象の予定・出欠・試合別スタメンも同時に読み、選手ごとの取得ループはありません。チームの定期取得は両revisionと週次記録を確認し、変更がなければ明細を読みません。予定保存後は未保存のオーダー編集がない場合にチーム情報を1回再取得し、反映された出欠を表示します。通常のチーム保存は反映後のデータと出欠をレスポンスに含め、追加取得を避けます。

`schedule_week` は内部の週次処理用で、APIの編集データには含めません。予定IDを伴わない既存オーダーでも、予定がなければ従来の情報を保持します。

## 手元での確認項目

- `0009` までの適用後に既存データが残り、同日2試合を別々に登録・編集・削除できること。
- メンバー本人は自分の出欠・コメントを編集でき、他人の回答は管理者だけが編集できること。予定編集者5名は予定の登録・編集ができても、管理者以外は他人の回答を変更できないこと。
- ログイン時に今日以降の未回答予定があれば案内し、明示的な未定・回答済み・過去の予定を案内対象に含めないこと。その場で回答でき、「あとで」や閉じる操作の後は同じ画面で再表示しないこと。
- 開始時刻・場所を変更すると、変更者以外の回答済みメンバーに変更前後を案内すること。「変更なし」は出欠・コメントを保ち、同じ変更を再案内しないこと。大会名・日付・相手・確定状況だけの変更では案内しないこと。
- スマホから予定を追加でき、既存の大会名・相手・場所を検索して選択したり新規追加・未設定へ変更できること。
- 予定が折りたたまれて並び、開いた予定の出欠入力と管理者の他人編集ができること。
- オーダーのスタメン・DH投手・ベンチ・不参加の各メンバーの背番号左に出欠が表示され、試合切り替え後に別の予定の回答を表示し続けないこと。
- 場所の検索中と保存済み予定からGoogle / Appleマップを開けること。場所候補が保存・再読み込み後も残ること。
- 試合のプルダウンを切り替えると各試合のスタメン・守備位置・DHが復元され、過去分だけが削除されること。チーム名・監督名は管理者だけが変更できること。
- 過去の予定が20件ずつ追加され、未来の予定の保存で未取得の過去予定が消えないこと。
- 対象予定の不参加がスタメン・DH投手から外れ、参加への変更でベンチへ戻り、未定・未回答では配置が保持されること。
- 土曜23:59と日曜0:00のJST境界、同日複数試合、時刻未入力、予定のない週、日曜以降の追加で対象が正しく決まること。
- 予定の変更とオーダー編集が重なった場合に競合を表示し、読み直した内容に回答・試合情報が残ること。

この変更ではDB接続・移行実行・LINE実送信・デプロイ・ビルド・ブラウザー操作による確認は実施していません。
